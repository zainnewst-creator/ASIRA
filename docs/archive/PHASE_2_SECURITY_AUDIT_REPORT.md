## 2. جدول الثغرات المكتشفة والإجراءات المتخذة (Vulnerability Register)

| :--- | :--- | :---: | :--- | :--- | :---: |

| **VULN-03** | انتحال دور المدير (Admin Spoofing) | **عالي (High)** | اعتماد شرط `isAdmin()` على البريد `admin@asira-research.org` دون فحص توثيق البريد `email_verified`. | إلزام التحقق من `request.auth.token.email_verified == true` ودعم Custom Claims كأولوية قصوى. | ✅ محصن ضد الانتحال |

| **VULN-06** | حقن روابط غير آمنة (DOM XSS / Malicious URIs) | **متوسط (Medium)** | إمكانية إدخال روابط ببروتوكول `javascript:` في روابط DOI و PubMed وملفات Drive. | إنشاء وحدة [security.ts](file:///e:/ASIRA/src/utils/security.ts) وتنظيف كافة الروابط بدالة `sanitizeUrl`. | ✅ تحصين كافة الروابط |

## 3. تفاصيل التحصين الدفاعي للمكونات (Remediation Details)

### 3.1 تحصين قواعد أمان فايربيس ([firestore.rules](file:///e:/ASIRA/firestore.rules))
1. **عزل مفتاح الحلول (Answer Key Isolation):**
   - مسار `/courses/{courseId}/exams/{examId}/answerKey/{secretDoc=**}` محظور كلياً على الطلاب بالقراءة والكتابة، ومتاح فقط للمدرس المعتمد أو المدير.
2. **سد ثغرة الدرجات والتقييمات:**
   - مسار `/officialGrades` و `/practicalGrades`: القراءة للطالب لدرجته فقط، والكتابة حصراً لـ `isAdmin() || isCourseInstructor(courseId)`.
   - مسار محاولات الاختبار `/attempts`: الطالب يسلم الإجابات الخام فقط بحالة `in_progress` أو `submitted` مع منع إرسال أو تعديل أي حقل متعلق بالدرجات.
   - مسار التكليفات `/submissions`: الطالب يسلم رابط الملف وممنوع إرسال حقول `grade`, `gradedBy`, `gradedAt`.
3. **حماية مسار الشهادات `/certificates/{certId}`:**
   - السماح للطلاب المعتمدين في الكورس بإنشاء طلب شهادة بحالة `requested` فقط، مع حظر إرسال رابط التوقيع `signedPdfDriveUrl` أو اسم المعتمد `issuedBy`؛ وتحديث الشهادة وإصدارها وتوقيعها محصور بالمدير فقط.

### 3.2 تحصين الواجهة الأمامية ([src/utils/security.ts](file:///e:/ASIRA/src/utils/security.ts))
تم إنشاء وتطبيق أدوات الأمان:
- `sanitizeUrl`: تعقيم روابط الأبحاث (DOI / PubMed) وروابط المستندات والشهادات لمنع هجمات XSS.
- `sanitizeInput`: تنظيف النصوص وتحديد الحدود القصوى للمدخلات.
- `isTrustedStorageUrl`: التحقق من نطاقات التخزين المعتمدة (Google Drive و Firebase Storage).
- `sanitizeExamForStudent`: عزل حقول الإجابات الصحيحة ونقاط الحل من عناصر الامتحانات المعروضة للطلاب.

### 3.3 فحص ترويسات الحماية في [index.html](file:///e:/ASIRA/index.html)
تم تضمين:
```html
<meta http-equiv="X-Content-Type-Options" content="nosniff" />
<meta name="referrer" content="strict-origin-when-cross-origin" />
```

### 3.4 تدقيق التبعيات ومكتبات الطرف الثالث (Dependency Audit)
- كشف فحص `npm audit` عن 4 تحذيرات في التبعية المتعدية `@grpc/grpc-js` المستخدمة في بيئة Node.js مع بروتوكول gRPC.
- تم الالتزام بقاعدة الأمان الصارمة (Rule 7: No blind dependency upgrades)، حيث أن الترقية القسرية لـ `firebase` كانت ستؤدي إلى الرجوع لإصدار قديم وكسر الاستيرادات المعيارية لـ Vite، وهي لا تشكل خطراً في المتصفح لأن كود العميل يعمل بـ Web SDK عبر REST/WebSockets وليس Node.js gRPC Server.
